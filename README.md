# go-pwa-template

Template for **Go + PWA hypermedia** applications: a single Go binary that serves
server-rendered HTML (templ), styles it with Tailwind CSS v4 + daisyUI, and makes the
page reactive/real-time with [Datastar](https://data-star.dev) over SSE — packaged as an
installable Progressive Web App. No React/Vue, no client-side router, no SPA build step
beyond CSS and templ codegen.

## Stack

| Layer | Tool | Notes |
|---|---|---|
| Server | Go 1.27 `net/http` | stdlib mux with method+pattern routes (`GET /`, `GET /static/`) |
| Templating | [a-h/templ](https://templ.guide) v0.3.1070 | `.templ` → generated `_templ.go` |
| Reactivity | [starfederation/datastar-go](https://data-star.dev) v1.2.2 + `static/datastar.js` (v1.0.4) | SSE-driven, `PatchElements` |
| CSS | Tailwind CSS v4.3.3 CLI + vendored daisyUI bundle (`style/*.mjs`, v5.7.x) | `--minify`, scanned sources = `tpl/*.templ` |
| Static assets | [vearutop/statigz](https://github.com/vearutop/statigz) | `//go:embed static`, precompressed at init |
| CLI flags | [alexflint/go-arg](https://github.com/alexflint/go-arg) | derived from the `Command` struct |
| Logging | stdlib `log/slog` + `github.com/nsf/rndgo/logu` (`Err`/`Err2` helpers) | level via `--slog-level` |
| IDs | [matoous/go-nanoid/v2](https://github.com/matoous/go-nanoid) via `internal/idlib` | 8 chars, base36 lowercase |

│   ├── daisyui.mjs       # vendored daisyUI bundle (~350 KB, MIT)
│   └── daisyui-theme.mjs # vendored daisyUI theme-definition plugin
├── static/               # SERVED from embed at /static/ (generated + vendored, do not hand-edit)

## Request / data flow

1. `GET /` → `serveIndexTemplate` renders `tpl.Index(viewCount)` to a `[]byte` under the
   server mutex and writes it with `text/html; charset=utf-8`.
2. The rendered root div carries `data-init="@get('/updates')"`, so Datastar immediately
   opens `GET /updates` as an SSE stream on page load.
3. `GET /updates` → `appServer.updates`:
   - wraps the writer with `datastar.NewSSE(w, r)`;
   - registers a `*session` (`startSession`) whose callback re-renders **only**
     `tpl.IndexContent` and pushes it via `sse.PatchElements(...)` — outerHTML swap of
     `#index-page`, no full reload;
   - increments the global `views` counter and, while holding the lock, fans the callback
     out to **every** connected session (so all open browsers re-render together);
   - then parks on `<-sse.Context().Done()` (client disconnect) or `<-s.est` (server
     shutdown), with `defer s.endSession(sess)` cleaning the map.

The demo payload is intentionally trivial (`"Page has been viewed N time(s)"`) — replace
`getPageStringUnlocked` / `IndexContent` with real domain data.

## Shared-state model

- `appServer` holds `lock sync.Mutex`, `views int`, `sessions map[string]*session`.
- One global lock guards both the counter and the session map; render happens inside it,
  so template rendering must stay cheap (or move rendering outside the lock).
- A session is `{id, callback}`: the callback closes over the SSE writer for that client.
  Fan-out is a broadcast to all sessions — there is no per-user targeting yet.
- `EventStreamTerminator` (a `chan struct{}`) is closed by `httpServer.RegisterOnShutdown`
  so all open SSE streams unblock during graceful shutdown.

## Shutdown

`SIGINT`/`SIGTERM` → `httpServer.Shutdown(ctx)` → registered on-shutdown hook closes the
EventStreamTerminator → every `/updates` handler returns → `wg.Wait()` lets the server
goroutine finish before exit. Note: `Shutdown` waits for long-lived SSE connections, which
is exactly why the terminator exists.

## Build

```sh
./build.bash      # idempotent; requires: go, tailwindcss (v4 CLI), templ, rsvg-convert, magick
go run . --addr 127.0.0.1:8000 --slog-level DEBUG
```

`build.bash` steps:
1. If `static/icons/` missing → rasterize `static-src/icon.svg` at 48/72/96/128/144/152/192/256/384/512 with `rsvg-convert`.
2. If `static/screenshots/` missing → `magick convert` the two SVG mockups into PNGs matching the sizes declared in `manifest.json`.
3. `tailwindcss --input style/style.css --output static/style.css --minify`
4. `templ generate`
5. `go build`

Steps 1–2 are skipped when the directories already exist — delete them to regenerate art.

## Dev loop

```sh
./watch-all.bash   # tmux session "myapp": tailwind --watch | templ generate -watch | air
```

Three panes: `.0` CSS watch, `.1` templ watch, `.2` `air` (Go hot reload). Requires a tmux
session available; nothing else orchestrates the three.

## Styling conventions

- `style/style.css` uses `@import "tailwindcss" source(none)` — Tailwind scans **only**
  explicitly declared sources (`@source "../tpl/*.templ"`). New template dirs must be added
  to `@source` or their classes will be purged from the build.
- daisyUI is loaded as a local plugin bundle, not an npm install: themes are pinned to
  `corporate --default, business --prefersdark`, with `corporate` overridden via
  `daisyui-theme.mjs`. Keep vendored `style/*.mjs` untouched on upgrades unless intentional.
- Custom variants for PWA display modes: `standalone:` and `fullscreen:` map to
  `@media (display-mode: …)`; the layout uses `h-dvh standalone:h-svh fullscreen:h-svh` to
  avoid viewport-height overflow when installed as an app.

## PWA notes

- `static/manifest.json` is linked from `tpl/head`; `theme-color` meta duplicates
  `theme_color` (`#202020`) in both manifest and template — change all three together.
- `display: minimal-ui`, `start_url: /`, fixed `id` UUID (regenerate when forking).
- **No service worker yet**: icons/screenshots make it installable-ish, but offline caching
  is not implemented. That is the main missing piece for a real PWA.
- Everything served is embedded (`//go:embed static`) — the binary is self-contained;
  `static/` must be populated before `go build` if you want icons/screenshots in the binary.

## Gaps / things to know before extending

- No `.gitignore`, no CI, no tests, no lint config; `static/icons` + `static/screenshots`
  are build artifacts that are not ignored and not present in a clean checkout.
- Generated files (`tpl/index_templ.go`, `static/style.css`) are committed — expect them to
  churn in diffs.
- CSS/JS assets are served with statigz's init-time compression but no explicit long-cache
  or fingerprinted URLs (no cache busting).
- SSE fan-out is a global broadcast; adding auth/user scoping means keying `sessions` by
  user and filtering in the loop.
